RAG 学习笔记：大语言模型（LLM）的工作原理

一、核心知识点概览

  1. LLM 的本质

根据已有上下文，预测下一个 Token，并不断重复，生成完整文本。

  1. 模型如何学习

通过大量文本训练，学习语言规律、知识关联和上下文模式，并调整内部参数。

  1. 为什么会产生幻觉

模型擅长生成看起来合理的内容，但合理不等于真实，尤其是在缺少相关信息时。

  1. RAG 如何改善回答

先检索相关资料，再把资料加入提示词，让模型根据这些上下文生成回答。

二、LLM 是如何生成文本的？

1. 本质：预测下一个 Token

视频用一个简单的英文句子解释：

What a beautiful day, the sun is …

模型可能预测出：

  • shining（正在照耀）
  • rising（正在升起）
  • out（出来了）
  • exploding（爆炸了）

其中，shining 可能是更符合语境的选择，但 exploding 在语法上也可能成立，只是不符合通常的现实情况。

这说明：模型生成的内容不仅受语法影响，还受训练中学到的语言模式和上下文关系影响。

严格来说，LLM 不是简单地预测完整的下一个单词，而是预测下一个 Token。

2. 什么是 Token？

Token 是模型处理文本的基本单位，可以是一个完整单词、单词的一部分、标点符号等。

例如，下面只是一个示意性的拆分，并不代表某个具体模型的实际分词结果：

原始文本

Unhappiness!

可能的 Token 划分

Un
happi
ness
!

采用 Token 机制有几个好处：

  • 不必为每个可能出现的单词都单独建立词表。
  • 可以组合较小的文本片段来表示生僻词和新词。
  • 标点、数字和多语言文本也可以通过 Token 进行处理。

3. 模型生成文本的完整流程

输入 Prompt（提示词）

问题、指令、对话历史、相关资料

分析当前上下文

通过神经网络计算上下文中的关联

计算下一个 Token 的概率分布

不同候选 Token 对应不同概率

选择并输出一个 Token

具体选择受解码策略等因素影响

重复上述过程，直到生成结束

注意：视频用随机选择来解释生成过程，方便理解。但实际模型不一定每次都随机采样，也可以采用贪心选择等解码策略。

4. 什么是自回归（Autoregressive）？

自回归是指：模型生成的每个新 Token，都会成为后续生成过程的上下文之一。

例如：

  • 第一种路径：太阳正在发光 → 照亮天空。
  • 第二种路径：太阳正在发热 → 温暖我们的脸。

前面选择的词不同，后续生成的内容也会不同。

这也解释了为什么同一个提示词在不同生成条件下，可能得到不同的回答。

三、LLM 是如何训练出来的？

视频介绍了模型训练的基本思路。

步骤 1：准备训练文本

收集大量文本数据，例如文章、书籍和互联网内容。

步骤 2：预测下一个 Token

向模型提供一段不完整的文本，让它预测后续内容。

步骤 3：计算预测误差

将预测结果与训练数据中的实际下一个 Token 进行比较。

步骤 4：更新模型参数

通过优化算法调整神经网络的参数，逐步改善预测能力。

模型经过大量训练后，能够学习到语言结构、事实关联、不同文体的特征，以及一定程度的上下文推理能力。

这里有一个重要区别：模型参数中学到的知识，并不等于一份可以直接检索、逐条核对的数据库。模型也不保证能准确回忆所有训练内容。

四、为什么 LLM 会产生幻觉？

幻觉（Hallucination）是指模型生成了看起来可信、实际上却错误或缺乏依据的内容。

视频重点强调了一个原因：

LLM 的训练目标与事实核验并不是同一件事。

模型学习的是如何根据上下文生成合适的 Token。虽然这种能力能够产生大量准确的回答，但也可能产生听起来很合理的错误内容。

例如，你问模型：

我们公司上周内部会议决定了什么？

如果模型没有接触过会议记录，它就缺乏回答这个问题所需的信息。即使它生成了一段流畅、具体的回答，也不能证明这些内容是真的。

常见的幻觉风险包括：

  • 编造不存在的事实、人物或事件。
  • 把多个真实信息错误地组合在一起。
  • 对不确定的问题给出过于肯定的回答。
  • 回答涉及最新新闻或内部资料的问题时，缺乏可靠依据。

因此，判断回答质量时，不能只看表达是否流畅，还要看内容有没有证据支持。

五、RAG 为什么能够改善 LLM 的回答？

这是本段视频最重要的结论。

RAG 的全称是 Retrieval-Augmented Generation，即检索增强生成。

它的核心思想不是要求模型凭空记住更多知识，而是在回答问题时，先为模型找到相关资料，再让模型利用这些资料回答。

普通 LLM 与 RAG 的区别

普通 LLM

用户提问

模型根据已有上下文生成回答

风险：缺少必要知识时，可能猜测或产生幻觉。

RAG 系统

用户提问

检索相关文档

问题 + 检索资料 → LLM

优势：为模型提供额外的事实依据和上下文。

举个例子，假设你在开发一个 UE5 项目，想让 AI 回答项目中的 GAS 使用规范。

普通 LLM 可能只能根据通用的 Unreal Engine 知识回答，而不一定知道你项目里的具体类名、蓝图配置和内部约定。

使用 RAG 后，可以先从项目文档、代码说明或开发规范中检索相关内容，再将其放进 Prompt，让模型依据这些材料回答。

这样，模型就有机会利用训练数据中原本没有的项目专属信息。

不过，RAG 不能保证彻底消除幻觉：如果检索结果不相关、不完整或过时，模型仍然可能回答错误。

六、为什么不能把所有资料都塞进 Prompt？

既然模型可以理解上下文，为什么不直接把整个知识库都交给它？

视频给出了两个主要原因。

限制 具体含义
计算成本 输入的上下文越长，处理它通常就越耗费计算资源与时间。
上下文窗口限制 模型一次能够处理的 Token 数量有限，输入可能超过上限。

上下文窗口（Context Window）是模型单次处理时能够容纳的上下文范围，通常以 Token 数量衡量。

例如，你的知识库有数千份文档，而用户只问一个具体问题。把所有文档都加入 Prompt，既浪费资源，也可能挤占真正重要的信息。

因此，RAG 不仅需要找到资料，还需要尽可能找到与当前问题相关、足够准确且数量合适的资料。

这就引出了接下来要学习的另一个核心组件：Retriever（检索器）。

七、本节必须记住的专业术语

术语 含义
LLM 大语言模型，Large Language Model
Token 模型处理和生成文本的基本单位
Prompt 提供给模型的输入提示与上下文
Completion 模型根据输入生成的后续文本
Probability Distribution 下一个 Token 的概率分布
Autoregressive 自回归，前面生成的内容影响后续生成
Parameters 神经网络中的可训练参数
Hallucination 幻觉，生成缺乏事实依据或不正确的内容
Context Window 模型单次处理的上下文容量
RAG 检索增强生成
Retriever 检索器，为当前问题寻找相关资料

八、最终总结

这一节可以归纳成下面四句话：

  1. LLM 通过预测下一个 Token 来生成文本。
  2. 模型通过大量训练数据学习语言模式和知识关联，但不保证每个回答都真实。
  3. RAG 通过检索外部资料并将其加入 Prompt，为模型提供额外的上下文依据。
  4. 上下文存在计算成本和容量限制，所以检索器必须筛选真正相关的信息。
